# Report a bug

Use the bug report workflow to submit a clear description of an issue you found. A good report helps maintainers reproduce the problem, evaluate impact, and decide the next action.

## When to report a bug

- A page, feature, or workflow does not behave as expected.
- You find broken content, incorrect behavior, or a usability issue.
- You find a security-related issue and the active BLT deployment is the appropriate place to report it.
- You have enough information for someone else to understand or reproduce the issue.

## Main actions

1. Sign in if the report form requires an account.
2. Open the bug reporting page.
3. Enter the affected site, application, domain, or project requested by the form.
4. Write a short summary that identifies the problem.
5. Add steps to reproduce the issue.
6. Describe the expected behavior and the actual behavior.
7. Attach evidence where appropriate, such as screenshots or relevant error text.
8. Review the report for clarity and remove unrelated or sensitive information.
9. Submit the report.

## Bug report quality checklist

- The affected page, site, or application is identified.
- The summary is specific.
- The steps to reproduce are ordered and complete.
- Expected and actual behavior are both included.
- Evidence supports the report without exposing secrets or private data.
- The report avoids duplicate submissions when a matching issue already exists.

## What to check

- Confirm that the issue is submitted under the correct target.
- Save or open the issue page after submission so you can follow updates.
- Watch for comments or status changes from maintainers.
- Add clarifying information if maintainers ask for it.
