# Issue page

An issue page shows the details and discussion for a single bug report. Use it to understand what was reported, review current status, and decide whether any follow-up is needed.

## When to use this page

- You want to read the full details of a submitted report.
- You need to check status, activity, comments, or related metadata.
- You are following up on a report you submitted.
- You are reviewing whether an issue needs triage, clarification, or action.

## Main actions

1. Open the issue from a report list, company page, profile, or direct issue link.
2. Read the issue summary and description.
3. Review status, labels, timestamps, reporter information, and other metadata shown on the page.
4. Check comments and activity for updates or maintainer requests.
5. Decide the next action, such as adding context, monitoring the report, or moving to a related workflow.

## What to check

- Confirm that the issue describes the correct affected site or application.
- Check whether the issue appears open, closed, duplicate, or otherwise triaged.
- Review attachments or evidence before drawing conclusions.
- Use optional features, such as bidding or voting, only where enabled by the active deployment.
