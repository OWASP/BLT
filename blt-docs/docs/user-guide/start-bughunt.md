# Start a bug hunt

A bug hunt is a coordinated BLT workflow for focusing reports on a defined target, organization, or scope. It should make expectations clear before users begin submitting reports.

## When to use this page

- You want to start or request a focused bug reporting activity.
- You are an organization or maintainer preparing a triage process.
- You need to define what is in scope before reports are submitted.
- The active deployment enables bug hunt creation or requests.

## Main actions

1. Confirm that you have permission to start or request a bug hunt.
2. Define the target, scope, rules, and any out-of-scope areas.
3. Prepare triage responsibilities, contact points, and expected response process.
4. Open the bug hunt workflow where enabled.
5. Enter the required details and submit the request or creation form.
6. Communicate expectations to participants through the channels provided by the deployment.

## What to check

- Scope is specific enough for users to know what to test.
- Rules do not encourage unsafe, illegal, or disruptive testing.
- Triage owners know who will review reports and respond to questions.
- Any reward, recognition, or participation terms are only those explicitly provided by the active deployment or project process.
