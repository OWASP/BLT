# Governance

OWASP BLT is an [OWASP Foundation](https://owasp.org) project
([project page](https://owasp.org/www-project-bug-logging-tool/)). It runs under the
[OWASP project policy](https://owasp.org/policy/project) and the
[OWASP Code of Conduct](https://policy.owasp.org/operational/code-of-conduct).

## How decisions are made

- Work is discussed in the open: issues, pull requests and discussions on
  [git.owaspblt.org/BLT](https://git.owaspblt.org/BLT), and `#project-blt` on the OWASP Slack.
- Pull requests are reviewed and merged by maintainers. Every pull request must meet the
  [AI Policy](https://git.owaspblt.org/BLT/blob/AI_POLICY.md), including the required AI model disclosure.
- Larger changes (a new project, retiring a project, changing licences or infrastructure) should start as an
  issue or discussion so the community can comment before work begins.
- Disagreements are settled by maintainer consensus; if that fails, the project lead decides. Disputes that can't
  be settled inside the project follow OWASP's
  [conflict resolution policy](https://policy.owasp.org/operational/conflict-resolution).

## Community leadership elections

Leads and co-leads for individual BLT projects are chosen by community election at
[pages.owaspblt.org/leaders.html](https://pages.owaspblt.org/leaders.html). Anyone can nominate themselves or another
contributor. A nomination is a `[NOMINATION]` issue on git.owaspblt.org, and the votes are the forge's issue votes,
one per account per role. The election pages live in [`blt-pages/`](https://git.owaspblt.org/BLT/tree/blt-pages).
